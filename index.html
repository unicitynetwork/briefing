AOS Protocol Schema and Docs Closed Out
Three PRs landed against the codewall-design branch to bring the AOS protocol specification to a consistent state. #4 added a tool_result corpus and an all_of match form to the protocol, extending the matching surface for structured AI outputs. #3 (area 1) reconciled gaps between the prose description and the JSON schema for the protocol cut dated 2026-08-07. #2 (area 3) corrected policy-versioning documentation to match the actual code and closed the open decisions recorded in §9, leaving no known prose-to-implementation drift.

Sphere28 PRs merged
Payments-v2 Stack Shipped End-to-End
The dominant work of the period was the full delivery and stabilisation of the payments-v2 money vertical. #727 built the wallet-api-only payment path from scratch across ten increments (P1–P10), and #728 executed the P11 flip making payments-v2 the sole money path and deleting all v1 code. #470 adopted the new SDK line in the Sphere frontend, #473 cleaned up the remaining v1 artefacts, and #732 added a connectionStatus() getter so late subscribers can receive the current connection state without missing the initial event (fixing the P1 gap reported in sphere#473). Two critical bugs were then patched: #735 fixed an unfalsifiable cross-network recipient guard by requiring callers to prove the network or explicitly signal it, and #736 corrected asset pricing to use the raw registry ID rather than the capitalised display name, which had been zeroing every from-side price in the swap UI (sphere#480). Infrastructure followed with #31 dropping the now-redundant RegistryUrl/RegistrySha256 CloudFormation parameters from the wallet-api stack.
sphere-sdk, sphere, sphere-infra
SDK 0.14.x Rollout and Connect Floor Raised
After the payments-v2 flip, the SDK was versioned through 0.14.1 and 0.14.2 and propagated across every consumer. #478 raised the Connect SDK floor to 0.14.1 and added deduplication of send intents to prevent double-spend races. The connect-example app was audited in #23 (0.13.1→0.14.1 migration) and three false documentation claims plus three real code defects were corrected in #24 and #25. #83, #43 (backoffice), #43 (dev-portal), and #22 (quest-frontend) each bumped to 0.14.2, and #84 defaulted SPHERE_WALLET_API_URL to the canonical wallet-api endpoint so operators no longer need to set it explicitly.
sphere, sphere-sdk, sphere-api, sphere-backoffice, sphere-dev-portal, sphere-quest-frontend, sphere-sdk-connect-example
Ratings, Moderation, and Appeals System
A full content-ratings and moderation capability was introduced across the stack. #82 delivered the ratings API with reversible moderation actions and the reports/appeals backend. #477 updated the Sphere frontend to surface moderation state to affected users and expose reporting and appeal flows. #42 (backoffice) added a ratings moderation queue and a reports/appeals management interface for operators, while #42 (dev-portal) surfaces project ratings in the developer portal for visibility. Together these PRs close the loop from user report through operator decision back to user-facing status.
sphere, sphere-api, sphere-backoffice, sphere-dev-portal
Catalog Paging, Filtering, and CSP Fixes
Two paired PRs fixed discoverability of the published marketplace catalog. #85 made the entire published catalog reachable via the API and added server-side filtering, replacing the previous client-side slice. #481 updated the Explore page to page through the full catalog, apply filters on the server, and expose an ordering control to users. Separately, #479 patched the Content Security Policy to allow the WebSocket origin used by the market feed, which had been blocked since the wss:// endpoint was not listed in the allowed sources.
sphere, sphere-api

Payments-v2 Stack Shipped End-to-End
Wave 1 of the control plane (#85) laid the call-context infrastructure, consolidated the dashboard, and loaded a rule engine that had previously been compiled but never wired in. Policy versioning was then formalised in #95 with immutable versions, publish/rollback, and archive transitions, and #94 moved the WebSocket authentication token from a query parameter to an Authorization header. #97 separated SIF and control-plane database migrations into disjoint version bands to prevent range collisions. #96 and #100 hardened deployment by pinning production to a named ref and image and recording the pinned image in .env rather than only in ephemeral shell state, and #104 switched the staging CI image pin from latest to head_sha.
semanticd
Rule Engine: Classification, Corpora, and Bug Fixes
The 94 shipped rules were fully classified for edge deployment in #99, and #98 introduced authored actions and corpora as first-class attributes separate from severity, giving operators finer-grained policy control. #88 added a destructive-command detection pack covering commands the model is about to execute. #102 tightened the pattern half of composite PII rules to reduce false positives, and #103 fixed rule example #41 (examples that cannot match their own rule) and added a test class covering the entire unmatchable-example category. #89 wired 127 database-gated tests against a Postgres service container in CI so they run on every pull request rather than being skipped.
semanticd
Protocol Wire Format and Schema Corrections
#111 gave unicode_normalize a wire form, expanding the normalisation rule count from 92 to 93 and making the transform reproducible across implementations. #110 moved artefact_hash out of the signed body and into the envelope, correcting a design flaw where a hash of the payload was itself inside the payload being hashed. #106 built the artefact compiler so that a published policy is compiled into a dumb edge artefact ready for distribution. #90 pinned the signed timestamp to microseconds in the receipt path, matching the precision already used by the store and eliminating a comparison mismatch.
semanticd
Snag Fixes, Guard Visibility, and Docs Hygiene
#105 and #101 fixed two related snags (4.22 and 4.19) where a store-substituted policy tier was invisible to the evaluation engine. #107 defaulted an omitted detectors field to an empty map so policies can be created from sif-dash without requiring callers to supply the key explicitly. #109 resolved three small but dangerous issues: a broken doctest, a loaded-gun default that could cause silent data loss, and a lost variable binding. #108 gave environment traps a tracked home in the documentation, and #91 replaced a wall-clock-dependent concurrency assertion in the engine test suite with a direct pool-concurrency check, making the test deterministic under load.
