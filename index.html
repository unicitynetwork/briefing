Astrid2 PRs merged
Rebrand off codewall.dev domain and hardening CI
PR #14 moves the schema $id namespace and installer host off the codewall.dev domain, a foundational rebrand step that ripples into downstream schema consumers. PR #13 (D3.25) consolidates CI so one check runs in one place and one deployment runs a single analysis path, eliminating duplicate or conflicting pipeline runs. Together these two PRs tighten identity consistency and CI determinism ahead of broader platform changes. Both were authored by @jvsteiner and set up dependencies referenced later in semanticd's own $id migration.

Sphere1 PRs merged
Prewarm payment source blobs on confirm screen
PR #754 adds prewarming of source blobs directly from the payment confirm screen, reducing latency perceived by users right before they finalize a transaction. By fetching and caching blob data ahead of the final confirmation step, the SDK cuts down on blocking network calls during the most time-sensitive part of the checkout flow. This is a targeted performance optimization to the payments module authored by @MastaP with no breaking API changes.

Console rebuilt with in-app user guide search
A major dashboard overhaul spans PR #134 (rebuild the console against the design of record), PR #128 (close gaps between console and management API), and PR #142 (ship the user guide inside the console behind a ⌘K command palette). semanticd
Session and access control hardening for admins
PR #132 fixes an authz bug where an admin could lock itself out of its own console, and PR #133 restricts deactivation so PATCH cannot perform it—only the dedicated POST routes can deactivate accounts. PR #127 ensures sign-out actually ends the session server-side rather than just clearing client state, closing a session-fixation-style gap. These three PRs, all by @jvsteiner, tighten the authorization and session lifecycle around dashboard access, reducing both lockout risk and stale-session exposure.
semanticd
Detector engine reliability and rule compilation checks
PR #131 refactors analysis so the centre runs only the heavy detectors, and introduces strict validation where a rule that fails to compile is treated as a hard error rather than silently skipped. PR #137 fixes the inference engine so workers stop missing queued jobs, addressing a job-loss bug in the queue consumption path by @jait91. PR #126 addresses eight essential findings from the #120 second-pass review across the plane and db layers. PR #138 fixes CI so the migration test no longer needs to ask Docker for a container, speeding up and simplifying test infrastructure. Together these harden both the correctness of the analysis engine and the reliability of its supporting test/CI plumbing.
semanticd
Re-vendor schema for the codewall $id migration
PR #139 re-vendors artefact.schema.json to reflect the $id namespace move initiated in codewall-design PR #14, keeping semanticd's schema copy in sync with the new canonical location. This is a direct downstream consequence of the astrid rebrand work, ensuring schema validation continues to resolve correctly against the new namespace. It's a small but critical dependency-tracking PR by @jvsteiner that prevents drift between the source schema and its vendored copy.
