Sphere27 PRs merged
Standalone SDK project type, end-to-end
PR #67 (sphere-api) introduces the standalone (SDK) project type, gating submission behind a repository check so only verifiable SDK-backed work qualifies. PR #36 (sphere-dev-portal) lets developers create and submit these projects, while PR #36 (sphere-backoffice) gives moderators the ability to review submissions and change a project's type after the fact. PR #467 (sphere) surfaces standalone projects in the Explore view and on the desktop. Together these PRs deliver the full vertical slice of the new project category across every layer of the stack.
sphere-api, sphere-backoffice, sphere-dev-portal, sphere
Repository check rate-limiting and submit-order optimisation
PR #70 adds a rate-limit on the outbound repository check, preventing abuse or runaway calls to external VCS hosts. PR #68 reorders the submission pipeline so cheap local checks run before the potentially slow outbound repo check, reducing unnecessary external traffic. These two changes harden the submit gate introduced alongside the standalone project type and improve overall API responsiveness under load.
sphere-api
Quest points, analytics, and achievements correctness fixes
PR #69 fixes a bug where standalone projects continued awarding quest points after a project-type change, causing inflated scores. PR #66 converts the all-time points total query from a COLLSCAN to an index-only scan, significantly cutting read latency for analytics aggregations. PR #65 addresses two related reliability issues: empty full scans were silently erasing wallet metrics, and the system was polling wallets that never respond, wasting resources.
sphere-api
Backoffice user filter UX and data-safety fixes
PR #34 (sphere-backoffice) adds audience mode to the project filter and introduces a filter bar that explains its active state to the operator. PR #35 (sphere-backoffice) corrects a UX defect where a refused filter silently rendered as an empty result instead of surfacing a clear refusal indicator. PR #64 (sphere-api) fixes the project audience filter when no address list is provided and includes two data-safety guards, ensuring partial or malformed filter inputs cannot corrupt query results.
sphere-backoffice, sphere-api
sphere-sdk legacy removal, test hygiene, and payment pipeline refactor
PR #722 is a breaking refactor that deletes the wallet.dat/legacy-file import path, the v1 TXF codec, bech32 address support, and the PROXY:// scheme, removing a significant surface area of deprecated infrastructure. PR #721 fixes all 332 test type errors in sphere-sdk and gates the test suite in CI, establishing a clean baseline for future changes. PR #719 and #715 together decompose and refactor the payments send path into discrete named steps and resume sends through the send's own pipeline, improving auditability and error recovery. PR #720 and wallet-api PRs #118 and #116 adopt state-transition-sdk 2.0.2 with parallel verification exposed as consumer config and align the mock-aggregator trustbase for local development. PR #117 (wallet-api) removes the asset-registry fetch and makes the trustbase the sole validation root, simplifying the trust model.
sphere-sdk, wallet-api
sphere-ui CSS containment and modal portal fixes adopted downstream
PR #23 (sphere-ui) fixes a CSS animation bug where the fade-in keyframe permanently promoted elements to a containing block, breaking stacking-context-sensitive layouts. PR #37 (sphere-dev-portal) renders dialogs in a portal so a transformed ancestor cannot displace them via the CSS transform containment rule. PR #22 (sphere-ui) makes the quests stat on project cards opt-in rather than always-visible, giving consumers control over information density. PRs #37 (sphere-backoffice) and #469 (sphere) adopt sphere-ui 0.1.37, propagating all three fixes to every consuming application. PR #468 (sphere) additionally makes the copy-to-clipboard action degrade gracefully in an insecure (non-HTTPS) context instead of throwing.
sphere-ui, sphere, sphere-backoffice, sphere-dev-portal
