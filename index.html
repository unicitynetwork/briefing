Astrid11 PRs merged
Installer resilience on slow and flaky connections
A cluster of fixes hardens the install pipeline against unreliable networks and interrupted runs. PRs #236, #229, #93, and #26 add reuse of verified Sigstore and runtime downloads, tolerate slow verifier fetches, and deploy a shared verifier cache with slow-link handling. PR #94 extends this to Oracle packs, reusing verified packs and keeping Claude registration intact across retries. PR #237 ensures abandoned release transactions are reclaimed after a retry instead of leaving install state corrupted. Together these changes cut redundant downloads and make installs recoverable rather than restart-from-scratch on poor connections.
aos-ce, oracles, unicity-aos.github.io
Console and tray crash recovery hardening
PR #239 recovers owned approval sockets after console crashes, preventing orphaned approval state from blocking future operations. PR #234 fixes the tray to read selected inventory as the actual operator rather than a stale or default identity. PR #232 makes hooks wait for cold principal responder readiness, closing a race condition on startup. These fixes target state consistency and timing issues that surface during crashes or cold starts, improving reliability of the AOS Community Edition desktop experience.
aos-ce
Oracle channel and release preparation fixes
PR #233 preserves the selected Oracle channel across updates, fixing a regression where channel selection was silently reset. PR #230 binds AOS dev preparation to an authenticated Astrid RC4 build, tightening the release pipeline's provenance guarantees. These two changes are smaller in scope but directly affect update correctness and release trustworthiness ahead of upcoming AOS builds.
aos-ce

Semanticd detector benchmarks get sharper and more honest
PR #465 brings the bm01/bm02 benchmarks in line with the current detector implementations, fixing stale assumptions baked into earlier tests. PR #469 adds per-detection attribution, counts failed requests, and records which models were used, giving much richer benchmark output. PR #472 labels the actual jailbreaks embedded among jailbreak_wild's otherwise regular prompts, improving ground-truth accuracy for jailbreak detection scoring. Together these changes make semanticd's benchmark suite both more accurate and more informative about where detectors succeed or fail.
semanticd
timestamp-cli ships as a real published package
PR #2 fixes four release-blocking defects that had been stopping timestamp-cli from shipping. PR #3 publishes the tool as @unicitylabs/timestamp-cli on the package registry, giving it a proper distribution channel. PR #4 reworks the release process to run from a workflow that owns the version, removing manual version-bump drift. PR #5 switches the version flag to -v for consistency with CLI conventions. This set of changes takes timestamp-cli from an internal tool to a properly packaged, versioned, and releasable CLI.
timestamp-cli
Wallet-agnostic labeling in the bridge
PR #25 reworks labels in unicity-bridge to be wallet agnostic rather than tied to a specific wallet implementation. This decouples UI/terminology from any single wallet's assumptions, making the bridge easier to integrate with multiple wallet backends going forward.
unicity-bridge
