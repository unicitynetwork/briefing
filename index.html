Sphere12 PRs merged
Coinless Tokens: Classify, Show, Transfer
A new token category — coinless tokens — was introduced end-to-end this cycle. PR #779 lays the groundwork: classifying, holding, showing, and recording coinless tokens in the SDK. PR #782 adds transfer support specifically for coinless tokens, while #783 generalizes this into sendWholeToken, a payments-v2 primitive that moves any token whole, coins included. PR #517 brings this to the wallet UI, letting users see and send coinless tokens directly in the Tokens tab. This is a coordinated SDK-to-UI feature rollout spanning four PRs.
sphere-sdk, sphere
Quest Prerequisite Reachability Fixes
Four PRs fix how the quest system handles prerequisites that can't be reached. PR #91 (sphere-api) adds server-side detection to tell the client when a prerequisite is no longer reachable. PR #27 changes the frontend to render such cases as a dead end rather than a misleading lock icon. PR #26 fixes a UI layout bug where track tabs didn't wrap, hiding later epochs. PR #25 stops the frontend from silently hiding quests whose prerequisite is missing from the payload. Together these close a class of bugs where players got stuck or confused by broken prerequisite chains.
sphere-quest-frontend, sphere-api
Wallet API Hardening & Infra Fixes
PR #160 switches CI to pull the MinIO test image from quay.io since Docker Hub's minio/minio was removed, unblocking test runs. PR #158 fixes a quota bug by recording mailbox-entry bytes and bounding them on the receive path, preventing unbounded storage growth. PR #155 corrects /v1/balances to derive active-only status from the query itself rather than relying on a fragile four-site naming convention. PR #153 hardens job tests by fencing on the §13 last-success gauge instead of a brittle handler side effect. These are reliability and correctness fixes across CI, quotas, balances, and test infrastructure.
wallet-api

Relay Access Control & Dependency Fix
PR #32 applies read access checks to live broadcasts in groups, closing a gap where restricted content could leak through real-time streams. PR #31 bumps the fiatjaf.com/nostr dependency to fix a khatru AUTH race condition. Both PRs harden the relay's security and correctness around access control and authentication.
unicity-relay
Semanticd Rule Engine & Publish Pipeline
A cluster of PRs reworks how semanticd classifies and publishes rules. PR #331 introduces a single unified publish act covering rules drift, preview, and Codewall drafts (issue 326), with #336 fixing the e2e tests to treat publish as its own call. PR #334 and #330 fix classifier logic so an ml_model rule never loses its classifier and an artefact-named ml_model rule correctly fires (closing out #311's B1). PR #329 stops the engine from recompiling unchanged rules on every write and timer tick, a performance fix for issue 325. PR #328 links dashboard alerts back to the rule that produced them (issue 324), and #335 adds make targets to serve the two 'understand-anything' code maps for developer tooling.
