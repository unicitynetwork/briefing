Sphere15 PRs merged
Announcements platform: backend model, Discord bridge, moderation
PR #71 lays the foundational announcements backend, introducing the data model, delivery pipeline, Discord bridge for ingesting chat-sourced posts, and moderation decision hooks. PR #72 extends this with hero-image persistence on create, forwarding that image to Discord on publish, and correcting formatting regressions introduced during import. PR #73 adds a bounded timeout to the attachment mirror upload so a hung external fetch can no longer wedge the inbound import pipeline. Together these PRs make the announcements feature production-safe from ingestion through delivery.
sphere-api
Announcements UI: backoffice composer, admin list, Discord bindings
PR #38 delivers the full backoffice surface for announcements, covering the admin list view, the post composer, and the UI bindings that connect Discord-sourced entries to their moderation controls. PR #39 adds hero-image preview of the pending (not-yet-saved) asset and removes a stale asset-id field that was leaking old state into new drafts. These changes give content administrators end-to-end visibility and control over announcements before they reach users.
sphere-backoffice
Announcement centre in wallet, quest portal, and developer portal
PR #472 mounts the announcement centre inside the wallet application, giving end users an in-app feed of platform announcements. PR #20 brings an equivalent announcement centre to the quest portal frontend. PR #38 in sphere-dev-portal adds a notification bell and a browsable archive for developers, ensuring all three major consumer surfaces expose the new feature consistently. This completes the front-end rollout of the announcements capability across every user-facing property.
sphere, sphere-quest-frontend, sphere-dev-portal
sphere-ui Discord icon, peer-dep fix, and downstream dependency bumps
PR #27 in sphere-ui introduces a Discord icon key specifically for labelling chat-sourced announcements in any consumer UI. PR #26 fixes the package's entry-point peer-dependency declarations by marking entry-specific peers as optional, preventing subpath consumers from being forced to install irrelevant peer packages. PRs #474, #21, and #40 in sphere, sphere-quest-frontend, and sphere-dev-portal respectively bump the sphere-ui dependency to 0.1.41 to pull in both changes. A separate PR #39 in sphere-dev-portal also upgrades @dnd-kit/sortable to ^10.0.0 to align with its upstream source repository.

RocksDB portable x86-64 build for aggregator-go
PR #175 introduces a build configuration for RocksDB that targets portable x86-64 rather than a host-tuned architecture, ensuring the compiled binary runs correctly across heterogeneous deployment environments. This is important for the aggregator-go service, which may be distributed to infrastructure nodes with varying CPU micro-architecture feature sets. Targeting a portable baseline eliminates the risk of illegal-instruction crashes on older hardware while keeping the performance characteristics of the native RocksDB storage engine.
