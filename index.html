Astrid20 PRs merged
Upgrade path hardening for AOS and Oracle installs
A large cluster of fixes targeted the upgrade and installer pipeline to stop stale or reactivated components from breaking deployments. PR #246 pins trusted distro upgrades to the Astrid RC6 release, while oracles #101 rejects old host pack reactivation after upgrades and #102 preserves committed receipts on preflight signals. Install ordering and stale Oracle activation guarding landed in unicity-aos.github.io #30 and #28, with #29 mirroring the reviewed upgrade repair. aos-ce #244 updates the CLI to show both AOS and Astrid versions and follow the release train, ensuring version visibility matches what actually got installed. Together these close race conditions and stale-state bugs that could leave hosts on inconsistent versions after an upgrade.
aos-ce, oracles, unicity-aos.github.io
Claude runtime recovery and auth repair in Codewall
Several PRs focus on keeping the Claude-backed runtime alive and authenticated through policy hooks and installer transitions. oracles #96 and #95 recover a stopped runtime and keep it available between policy hooks, while oracles #99 mints portable secure session tokens on minimal hosts to support this. codewall #138 fixes Claude auto-fix authentication and failure reporting, and #137 reports Oracle runtime availability in public status so operators can see failures sooner. codewall #141 waits for macOS service transitions during upgrades, addressing a platform-specific timing bug that previously caused install failures. These changes reduce silent runtime drops that had been causing downstream Claude integration failures.
codewall, oracles
Installer diagnostics and provisioning reliability
This theme covers fixes to installer internals that improve diagnosability and avoid redundant work. codewall #139 repairs migration diagnostics and restores Claude inventory compatibility, and #134 reuses verified work while showing provisioning progress to the user instead of re-running completed steps. oracles #97 reconciles recognized stale default AOS dependencies that were causing installer mismatches. aos-ce #241 surfaces nested provider delivery failures in MCP so errors propagate instead of failing silently. These changes collectively make installer failures easier to triage and reduce wasted re-provisioning cycles.
codewall, oracles
October release documentation catch-up
Three docs-only PRs bring release notes up to date with the October patch cycle. aos-ce #245 includes the AOS version and updates repair notes, #242 rolls up October integration repair notes, and oracles #100 describes the October hook and upgrade repairs. These ensure the documented behavior matches the shipped fixes from the upgrade-hardening and runtime-recovery work landed this week.

Expanded jailbreak and prompt-injection training data
MastaP landed a wave of model training updates to harden semanticd's detection of adversarial prompts. #489 adds injection techniques paired with their benign twins, #488's referenced work, #487 and #483 add real in-the-wild jailbreaks with benchmarks held out, and #475 covers long role-play jailbreaks against benign versions. #476 trains a prompt_injection model variant (103c8b72) using long benign documents and requests, and #474 supplies long benign texts and ordinary requests for both classifiers to reduce false positives. This set substantially broadens the negative and positive examples the classifiers see, aimed at cutting both missed jailbreaks and false flags on legitimate long-form content.
semanticd
DLP/NER false-positive reduction for PII detection
Two PRs refine the dlp_ner model's handling of entities that look like PII but aren't. #484 marks code words, commands, and titles as not-PII, and #473 adds NER shape checks, recording lone places and companies while capturing code negatives. These changes directly target over-flagging in the DLP pipeline, improving precision for enterprise text scanning without loosening true PII detection.
semanticd
Central-analysis preflight and runtime verification fixes
A set of jvsteiner PRs hardens the preflight checks gating uploads to the central-analysis runtime. #482 makes pre-flight refuse uploads without an available analysis runtime, #481 aligns Codewall's central-analysis runtime checks with setup guidance, and #480 fixes central-analysis publication preflight while verifying encrypted ingestion end-to-end. #485 resolves the Astrid ref from the codewall SERVICE_RUNTIME pin for e2e tests, tying semanticd's test pipeline to the same Astrid RC6 pin used in unicity-aos. #471 reworks the engine to scan a request's buffers one at a time per detector, improving memory behavior during scanning.
semanticd
OpenClaw plugin packaging and CI improvements
openclaw-unicity shipped packaging and build updates: #11 ships a plugin icon for v0.6.1, #10 checks the packed tarball directly in CI before publishing to catch packaging regressions earlier, and #9 rebuilds the plugin on Sphere SDK 0.18.1 and OpenClaw 2026.10.2 to track upstream dependency versions. These changes tighten the release pipeline for the plugin and keep it aligned with current SDK releases.
