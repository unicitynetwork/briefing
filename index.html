Astrid2 PRs merged
Installer E2E tests consolidated into Codewall CI
PR #180 moved the public installer end-to-end tests from their previous pipeline into Codewall CI, centralizing test execution. PR #182 followed up by wiring those installer E2E results into the main CI status check, so a failing installer test now blocks merges rather than running silently on the side. Together these changes close a gap where installer regressions could slip through without affecting the visible CI signal. This gives contributors a single source of truth for build health.
codewall
Sphere4 PRs merged
SSRF hardening pins validated address on outbound calls
PR #97 fixes a DNS-rebinding-style SSRF gap by pinning the already-validated IP address onto the actual outbound connection, rather than re-resolving the hostname after validation. This closes the window where an attacker-controlled DNS record could swap the resolved address between the validation check and the real request. The fix is scoped to sphere-api's outbound connection handling and directly hardens any feature that fetches user-supplied URLs.
sphere-api
External API status shown accurately across integration surfaces
PR #96 disables EXTERNAL quest verification platform-wide, and the remaining PRs update the UI/UX to reflect that honestly. PR #53 makes both admin screens in sphere-backoffice report External APIs as unavailable instead of showing stale or misleading status. PR #51 updates sphere-dev-portal copy from a vague 'coming soon' to a clear 'unavailable' message, avoiding false expectations for developers. All three PRs by @KruGoL ship together as a coordinated rollback-and-communicate effort around the External API feature.

Unicity Network6 PRs merged
Shared BFT base library bump across core services
PR #53 and PR #274 both bump their dependency on bft-go-base to v1.2.0, keeping bft-core and aggregator-go aligned on the same underlying BFT primitives. Standardizing this version reduces the risk of subtle consensus-logic mismatches between the two services. This is a low-risk maintenance update by @MastaP that unblocks downstream work relying on the newer base library.
bft-core, aggregator-go
Trust Base v2 ships weighted BFT quorum across all SDKs
PR #101, #206, and #73 bring an identical, API-breaking v4.0.0 upgrade to the Java, JS, and Rust SDKs respectively, introducing weighted BFT quorum support where votes carry unequal weight instead of one-vote-per-node. Seals are now verified against the trust base entry belonging to their own epoch, fixing a class of bugs where epoch transitions could use the wrong validator set. All three add release pins, a local trust-base cache/file store, a GetTrustBase fetch loop, and a new X-SDK-Version header for better server-side version negotiation. Because this is API-breaking, downstream consumers of these SDKs will need migration work when adopting 4.0.0.
state-transition-sdk-java, state-transition-sdk-js, state-transition-sdk-rust
Aggregator serves Trust Base v2 history via new endpoint
PR #273 adds a GET /api/v1/trustbases endpoint that serves the Unicity Trust Base v2 history from a configured bundle. The history can be extended only by entries that pass weighted-quorum verification, preventing unverified trust base updates from being served. This feature is config-gated and explicitly non-breaking, letting operators opt in before the wider v2 rollout lands. It complements the SDK-side v2 work by giving clients a canonical, verifiable source for historical trust base data.
aggregator-go
