Sphere15 PRs merged
Analytics fixed and enriched with track content counts
PR #63 resolved the 500 errors hitting the analytics endpoints in sphere-api, restoring reliable data delivery to the admin surface. Alongside the fix, it adds content-count tracking scoped to tracks, giving operators a new dimension of usage insight. On the backoffice side, PR #31 changes analytics rendering from an all-or-nothing page load to a per-card model, so a single slow query no longer blocks the entire dashboard. Together these changes make the analytics layer both more resilient and more granular for admin workflows.
sphere-api, sphere-backoffice
Admin navigation wired from tracks to quests and achievements
PR #32 in sphere-backoffice adds direct navigation from a track record to its associated quests and achievements, eliminating manual filtering steps for content managers. PR #35 in sphere-dev-portal extends quest tracking to cover navigation events, content filters, and switches table views in place of cards, aligning the dev portal's UX with the backoffice pattern. These changes collectively tighten the editorial workflow around track-based content and improve data fidelity for quest engagement metrics.
sphere-backoffice, sphere-dev-portal
SDK payments stack stripped of legacy rails and IPFS machinery
A concentrated series of breaking refactors (PRs #707–#711) removed the Nostr payment-request channel, the Nostr token-delivery rail, the archived TXF token stores, and on-chain memo accounting, cutting the codebase from roughly 6,912 to 6,454 lines. PR #711 reduces payments.sync() to a simple flush, discarding the IPFS-era merge machinery that had accumulated technical debt. PR #712 advances end-to-end tests to run against the real staging wallet-api rather than stubs, and PR #714 adds concurrency pinning tests for PaymentsModule to catch contention under simultaneous sends. The net result is a leaner, better-tested payments layer with no dependency on deprecated Nostr or IPFS infrastructure.
sphere-sdk
Security headers, wallet attribution, and group invite fix
PR #463 introduces a Content-Security-Policy header and the supporting HTTP headers required to carry it, establishing a baseline browser-enforced security boundary for the Sphere web client. PR #465 wires wallet identification at sign-in so that user activity is correctly attributed to the wallet from the moment of authentication, closing a gap in attribution data. PR #464 fixes a regression in group chat where invite links were silently failing, restoring a core social onboarding path. The sphere-infra PR #30 also bumps the RegistrySha256 for the testnet2 SNAKE asset, keeping the wallet-api registry in sync with the latest testnet state.
