Astrid2 PRs merged
Schema namespace and installer host migration
PRs #14 and #13 together complete the move of the artefact schema $id namespace and installer host away from the codewall.dev domain. #14 updates the namespace reference directly in the schema, while #13 enforces the area-3 constraint that a single check runs in exactly one place and a single deployment follows exactly one analysis path (D3.25). Together these changes tighten the architectural boundary between deployment stages and ensure the schema is owned by the correct canonical host going forward.

Sphere1 PRs merged
Payment confirm screen blob prewarming
PR #754 introduces prewarming of source blobs from the payment confirm screen in the Sphere SDK. By fetching the required blobs before the user completes confirmation, the SDK reduces perceived latency at the moment the payment is actually submitted. This is a targeted performance improvement to the payments flow and has no effect on the confirmation logic itself.

Unicity Network14 PRs merged
Console dashboard rebuilt and feature-complete
PRs #134 and #128 rebuild the semanticd console against the current design of record and close the remaining gaps between the dashboard UI and the management API. PR #142 adds a searchable user guide surfaced inside the console behind the ⌘K shortcut, making operational documentation available without leaving the interface. The CI pipeline was extended in #143 to publish the user guide on the self-hosted runner, and #144 fixes the Docker dashboard stage so it receives the docs corpus the guide now depends on at build time. PR #127 corrects a session management bug where sign-out was only cleared client-side, and the session is now properly terminated server-side.
unicitynetwork
Authorization hardening and PATCH route constraints
PRs #133 and #132 address two related authorization correctness issues in semanticd. #133 enforces that the PATCH route cannot be used to deactivate a principal and that the POST routes are the sole authoritative path for that operation, preventing an unintended deactivation vector. #132 adds a guard that prevents an admin from revoking its own console access, closing a self-lockout scenario. These changes make the authz layer more predictable and operationally safer for multi-admin deployments.
unicitynetwork
Analysis engine correctness and inference worker reliability
PR #131 restructures the analysis centre so that heavy detectors run exclusively at the centre tier and introduces a compilation-time error for any rule that cannot be compiled, surfacing configuration mistakes earlier in the pipeline. PR #137, contributed by @jait91, fixes a race condition in the inference worker scheduler where workers could miss jobs that had been queued but not yet dispatched. PR #126 applies eight targeted correctness fixes to the plane and database layers identified during the second review pass on #120, addressing accumulated edge cases across persistence and request handling.
unicitynetwork
Schema re-vendor, CI fixes, and docs housekeeping
PR #139 re-vendors artefact.schema.json to align with the $id namespace move landed in unicity-aos #14, keeping the schema reference consistent across repositories. PR #138 fixes the migration test CI job, which had incorrectly been asking the Docker daemon for a running container rather than operating against the test fixture. PR #140 removes a now-stale caveat in verify-artefact.sh that warned about an unmerged codewall-design PR, keeping the script documentation accurate after the underlying PR was merged.
