Sphere2 PRs merged
Propagate sender Unicity ID through payment delivery
PRs #489 (unicity-sphere) and #750 (sphere-sdk) together close issue sphere#487 by carrying the sender's Unicity ID on every incoming payment delivery end-to-end. The sphere-sdk fix in #750 attaches the identifier at the payments-v2 transport layer so it survives the full delivery pipeline, while #489 wires that field into the sphere consumer. Previously the recipient had no reliable way to identify the sending party from within the payment event itself, which blocked downstream attribution and compliance flows.

Unicity Network7 PRs merged
Multi-tenant SaaS control plane: core and enrolment
PRs #114 and #112 form the foundational layer of the multi-tenant SaaS control plane in semanticd. PR #112 brings up the artefact store and enrolment flow, making the fleet operational for the first time. PR #114 builds the broader control-plane scaffold on top, enabling per-tenant lifecycle management at the SaaS layer. Together they represent the transition from single-tenant semanticd to a production-grade multi-tenant service.
semanticd
Tenant key rotation: signing and endpoint forwarding
PRs #115 and #118 harden how semanticd handles tenant key generations. PR #115 switches plane signatures to use the tenant's current key generation rather than a hardcoded constant, closing a correctness gap that would have caused verification failures after any key rotation. PR #118 complements this by walking plane endpoints forward automatically when a tenant key rotates, so downstream consumers always resolve to a live, correctly-keyed endpoint without manual intervention.
semanticd
Database boot hardening and RLS startup safety
PRs #116 and #119 address two distinct database safety concerns in semanticd. PR #116 refuses single-URL database boot outside dev mode, preventing accidental production deployments against an under-replicated or misconfigured database endpoint. PR #119 catches 021-era row-level security policy violations at startup and documents the comment-edit trap, ensuring operators see actionable errors rather than opaque runtime failures when legacy RLS policies are present.
semanticd
Parallel-safe cleanup for plane isolation tests
PR #117 fixes a race condition in the plane isolation test suite's cleanup logic that caused flaky failures when tests ran in parallel. The change makes teardown safe to execute concurrently, removing a source of non-deterministic CI failures that could mask real regressions. This is particularly important now that the control-plane feature set is expanding rapidly across multiple contributors.
