Codewall Policy Routed Through Oracle-Owned Hooks
A major rework moved Codewall policy enforcement through Oracle-owned host adapters, with #99, #79, and #205 ensuring native decisions and authenticated policy survive the Oracle relay without losing custody of protected registrations. #96 adds forwarding of encrypted content for asynchronous central analysis, feeding the new decision pipeline. #59 complements this by reporting Claude project MCP inventory through hooks, giving the Oracle layer visibility into connected tooling. Together these PRs harden the trust boundary between local hooks and the central Oracle service.
codewall, oracles, aos-ce
Command Center Discovery and Verified Updates
#199 introduces Command Center discovery alongside verified update delivery, and #76 backs it with signed Oracle discovery and registration state exposure. #200 ensures the default fleet is granted correctly during first runtime init, fixing a gap in fresh installs. #204 improves resilience by tolerating regular Finder metadata after shutdown, reducing false status errors. These changes collectively make update and fleet management more trustworthy and robust across restarts.
aos-ce, oracles
Installer Reliability and Claude Plugin Integration
#105 fixes installation reliability issues and integrates the AOS Claude plugin, smoothing onboarding for Claude-based workflows. This complements the hook-based policy work landing in the same repo this period. Combined with #59's MCP inventory reporting, the Codewall/Claude integration surface is becoming noticeably more complete.
codewall
Audit Console Noise Reduction
#4 updates the audit console to hide quiet entries by default while still exposing full entry details in the receipt panel on demand. This reduces noise for operators reviewing audit trails while preserving drill-down capability for investigations. It's a small but meaningful usability upgrade for anyone monitoring Oracle/Codewall decisions.
aos-audit

Cross-Chain Bridge Module Lands in Wallet
#529 introduces a full bridge module enabling assets to move in and out of Unicity through wallet modules, a significant new capability for interoperability. #531 restricts the bridged label, balance, and send actions to verified tokens only, tightening safety around bridged assets. #826 adds issuance proof requirements for token types and ensures coins they claim only count within verified tokens, reinforcing the trust model underpinning the bridge. These PRs together establish the client-side foundation for Unicity's asset bridging feature.
sphere, sphere-sdk
dApp Network Switching and Token Plugin Flexibility
#533 improves dApp connection UX by offering to switch networks instead of outright refusing a connection request, reducing friction for users on the wrong chain. #822 expands token plugin capabilities with custom-genesis minting, burn-with-reason, and mint justification reads, giving issuers finer control over token lifecycle events. Both changes broaden what wallet-integrated dApps and token issuers can do without compromising existing verification flows.
sphere, sphere-sdk
