Astrid10 PRs merged
Streamlined Codewall installation and Claude provisioning
The installation flow for Codewall and Claude was consolidated into a single command, with PR #3 in codewall-capsules simplifying the docs and PRs #56, #57 in codewall reordering the flow to provision Claude before Codewall enrollment and auto-select the Claude principal. New documentation capsules (#1, #2) explain public Claude installation and announce the published Codewall 0.1.0 release. On the AOS install side, #20 in unicity-aos.github.io adds an eager Oracle provisioning handoff, completed by #77 in oracles reporting finished Oracle principal provisioning. Together these changes remove manual steps and tighten the handshake between AOS, Codewall, and Oracle provisioning.
codewall, codewall-capsules, unicity-aos.github.io, oracles
macOS compatibility and stable plugin reconciliation
PR #202 in aos-ce and #21 in unicity-aos.github.io ensure AOS installs and remains usable on older macOS versions by gracefully skipping unsupported desktop components. This addresses a class of install failures on machines lacking optional apps. Complementing this, #49 in codewall changes default behavior to reconcile stable AOS and plugin versions automatically, reducing drift between installed components. These fixes collectively harden the install experience across heterogeneous macOS environments.
aos-ce, unicity-aos.github.io, codewall

SDK version bump to 0.17.6 across the stack
A coordinated upgrade moved the SDK pin to 0.17.6, touching docs (#528 in sphere), the connect example's five packages plus a new mint_nft demo (#29 in sphere-sdk-connect-example), and the Claude marketplace skill resync with SDK 0.17.2 while dropping a dead extension recommendation (#15). PR #526 in sphere also bumped to sphere-sdk 0.17.5 as an intermediate step while fixing wallet-clearing behavior. This wave of changes keeps documentation, examples, and integrations aligned with the latest SDK release cadence.
sphere, sphere-sdk, sphere-sdk-connect-example, unicity-claude-marketplace
Wallet load/write and import reliability fixes
PR #817 in sphere-sdk fixes a critical nodejs bug where the wallet file wasn't loaded before the first read or write, closing out issue #811. Building on this, #526 in sphere prevents the wallet from being cleared when the SDK refuses to overwrite it, avoiding silent data loss during import. These fixes target core wallet integrity, a foundational concern for any SDK consumer handling key material.
sphere, sphere-sdk
Dead UI features and release process cleanup
PR #527 removes the activity ticker from the Sphere UI since its backing service no longer exists, eliminating a broken feature. On the release engineering side, #819 in sphere-sdk fixes the CHANGELOG dating in the publish job while ensuring the release commit still lands correctly, improving release automation reliability. Both changes are small but reduce technical debt and prevent user-facing confusion or broken release artifacts.
sphere, sphere-sdk
Connect docs and browser intent-handling fixes
Multiple PRs improve Sphere Connect's documentation and reliability: #524 makes the /developers/docs samples run against a real wallet instead of mocks, #28 corrects the Connect surface, local-testing path, and tsconfig paths in the example repo, and #49 in sphere-dev-portal aligns the Connect page with Connect 2.3. On the code side, #27 fixes a browser bug where an intent could be incorrectly re-enabled after receiving INTENT_OUTCOME_UNKNOWN (error 4201), preventing confusing retry states. Together these ensure developers get accurate docs and a more robust Connect intent lifecycle.
sphere, sphere-sdk-connect-example, sphere-dev-portal
