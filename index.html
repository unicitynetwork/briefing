Mainnet Onboarding: Trust Base and v3 Gateway
PR #765 is a breaking change that onboards the SDK to mainnet, embedding the trust base directly and switching to the v3 gateway. It pins networkId to 1 and strips out every remaining v1 pointer, closing the door on legacy testnet-era configuration. This is a major milestone for Sphere as it moves from test infrastructure to production network support. Consumers of sphere-sdk will need to update integrations to account for the removed v1 code paths.
sphere-sdk
Unicity Network18 PRs merged
CI Auto-Fix Pipeline for QA-Flagged Issues
A new Claude-driven auto-fix workflow lets QA label an issue and have an agent open a draft PR automatically, introduced in #219. Follow-up hardening in #223 makes a refusal to act a hard CI failure rather than a silent no-op, and #221 ensures the pipeline reports accurately when it fails to open the auto-fix PR. Supporting groundwork in #217 adds structured GitHub issue forms and disables blank issues to feed the pipeline cleaner input. Together these changes make the auto-remediation loop trustworthy and observable rather than best-effort.
semanticd
Test Infrastructure: Faster, Isolated, Honest DB Gates
A cluster of PRs overhauls the Postgres-backed test harness: #210 caps the DB gate at 20 test threads sized against max_connections, #206 lets DB jobs grab a free port and adds timing instrumentation to diagnose slowness, and #208 stops the test Postgres from issuing flushes so it no longer needlessly persists data. #200 stabilizes cleanup for parallel tenant isolation tests, and #205 adds dedicated isolation checks for registry enforcement. #207 runs clippy alongside tests and stops shipping the target/ build directory to GitHub, trimming CI noise and artifact bloat.
semanticd
Policy Engine Redesign: Rulesets, Rules, and Settings
PR #198 reworks the core policy model so a policy now names its rulesets and each rule owns its own settings, a structural change that ripples through related fixes. #204 fixes the e2e smoke test to require that a caller-led key names its policy under the new model, and #199 addresses the capability catalogue (issue #191) to align with the redesign. #201 adds NFKC Unicode normalization in rule matching to prevent bypass via lookalike characters. #203 extends registry routes to support path-like agent class slugs, broadening how policies can be addressed.
semanticd
Content Classification and Control-Plane Testing
#148 introduces a multi-label harmful_content topic/intent classifier with runtime integration, shipped disabled by default pending validation. #170 delivers a runnable end-to-end test for the Codewall control plane along with a guide, giving the team a repeatable verification path. Separately in smt-explorer, #4 fixes block search functionality when operating in All Shards mode, correcting a cross-shard query bug. These changes expand both safety tooling and cross-repo test/debug coverage.
semanticd, smt-explorer
