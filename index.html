Standalone AOS Install Fixed Without Coding Agent
PR #32 fixes the standalone installation path for AOS when no coding-agent host is present. Previously the installer assumed a coding-agent environment, breaking setup for users running AOS independently. This unblocks adoption for users who want AOS without the full agent stack.

Sphere1 PRs merged
Payment Resume Hardened Against Bad Intents
PR #854 fixes a bug where a single malformed or foreign open payment intent would halt the resume process for all pending intents. The fix isolates faulty intents so they no longer block processing of valid ones. This closes out issue #840 and significantly improves resilience of the payment resume flow in production.
sphere-sdk
Unicity Network29 PRs merged
Recovery and Consensus Hardening in BFT Core
A major security and correctness push across the consensus layer: PR #246 hardens certification-response intake in aggregator-go with admitted root peers, authenticate-before-liveness, and bounded catch-up. PRs #45, #46, #48, #50, #51 progressively fix recovery logic to reject peer-supplied nulls in StateMsg, bind live QCs and recovered state to the committed root, and improve vote admission and fuzz fixture lifetime. PR #19 in bft-go-base rejects nil hash steps instead of panicking (fixes #17), with the fix propagated through #258 and #260. PR #47 also fixes a flaky zero-round-trip network test. Together these close a class of crash and liveness bugs triggered by malformed peer data during recovery.
bft-core, bft-go-base, aggregator-go
Long-Poll Default Adopted Across All SDKs
The team standardized a 15-second default proof-wait budget and long-poll-by-default behavior across JS (#196), Rust (#62, #61), and wired equivalent transport logic into Java (#87). The aggregator-subscription service gained a new gateway route for get_inclusion_proofs.v1 by stateIds with long-poll notes (#85), and aggregator-go synced non-inclusion handling into the long-poll path (#260). This cross-language parity effort reduces polling overhead and unifies client behavior for inclusion-proof waits across all three supported SDK languages.
state-transition-sdk-js, state-transition-sdk-rust, state-transition-sdk-java, aggregator-subscription, aggregator-go
Non-Inclusion v2 Manifest Synced Everywhere
Non-inclusion proof handling was upgraded to manifest v2 and merged into the long-poll pipeline: Rust re-vendored the NI v2 manifest from aggregator-go commit 02263dd (#56, #57), and JS did the same (#191, #192). aggregator-go itself synced uc-consolidation into non-inclusion (#259) before propagating it into long-poll (#260). This keeps all clients and the aggregator aligned on the same non-inclusion proof format and semantics.
state-transition-sdk-js, state-transition-sdk-rust, aggregator-go
Java SDK Reaches Feature Parity With JS/Rust
Three parity PRs bring the Java SDK up to speed: #88 adds certificates, verification reuse, and explicit consolidation; #87 adds status-aware transport, long-poll wait, batch and non-inclusion HTTP support, resubmission, and docs; #86 adds snapshot-scoped non-inclusion handling. This closes the feature gap between Java and the more mature JS/Rust SDKs, enabling consistent client behavior across all supported languages.
state-transition-sdk-java
SDK Docs Trimmed and Restructured
A documentation cleanup pass moved detailed API content out of READMEs into dedicated references: Rust's #58 moved API details to docs/api-reference.md, #59 and #60 shortened the non-inclusion section and trimmed the README further. JS mirrored this with #193, #194, and #195, moving API details to the protocol spec and adding a long-poll note. The result is leaner, more maintainable onboarding docs with technical depth relocated to proper reference material.
state-transition-sdk-js, state-transition-sdk-rust
