Codewall gate contracts take shape
PR #82 introduces bounded gate IPC with a protected stream contract, establishing the low-level channel used to isolate privileged operations. PR #22 probes the protected evidence boundary to pin down that stream contract's semantics, while PR #20 defines the broader security workstreams and a v2 policy generation contract that will govern how gates are configured going forward. Together these PRs lay the architectural groundwork for codewall's protected service model. PR #95 complements this by fixing ETXTBSY flakiness in the protected service manager test suite, ensuring the new IPC and contract work can be validated reliably in CI.
codewall, codewall-design
Live audit console with fork detection
PR #3 adds a live audit console that surfaces anchoring evidence lines in real time, giving operators visibility into the audit trail as it's generated. It also introduces an engine fork check, detecting divergence in the underlying engine state that could indicate tampering or inconsistency. This is the first substantive feature in aos-audit, pairing monitoring UX with a concrete integrity check. It establishes a foundation for surfacing trust signals that other Unicity components, like semanticd's trust reporting, can build on.
aos-audit

Surfacing trust and audit gaps at the edge
PR #406 adds reporting for endpoint-reported trust alongside observed audit gaps, giving operators a combined view of what endpoints claim about their own trust state versus what the system actually observes. This helps identify discrepancies between self-reported and externally verified trust, a key signal for detecting misbehaving or compromised nodes. It complements the audit tooling work happening in aos-audit by feeding network-level trust data into the broader audit ecosystem.
