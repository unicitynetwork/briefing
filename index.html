Sphere SDK 0.15.0 Flag Day Across Fleet
This is a coordinated major-version rollout: state-transition-sdk bumps to 3.0.1 (request deadlines + reference time) shipping as sphere-sdk 0.15.0 (#761), consumed by sphere (#493), wallet-api (#134, marked as a breaking flag-day change), agentic-chatbot (#17), and sphere-infra's chess-bot (#35). The agentic-chatbot upgrade also fixes two stranded-reward bugs uncovered during the bump. This touches nearly every service that depends on the SDK, making it the dominant theme of the weekend's work. Careful sequencing across repos was needed to avoid breaking wallet or bot behavior during the transition.
sphere-sdk, sphere, sphere-infra, wallet-api, agentic-chatbot
Wallet Correctness and Reset Runbook
PR #494 fixes a wallet classification bug where a self-mint credit was incorrectly treated as a send instead of an incoming credit (addressing #488). PR #33 implements a 'wire-break reset' for wallet-api that preserves history and identity across the reset, and #34 corrects two contradictions in the reset runbook that Codex caught during review. These changes tighten up wallet semantics and operational reset procedures ahead of the SDK 3.x transition. Together they reduce the chance of data loss or miscategorized transactions during resets.
sphere, sphere-infra
CI Reliability for Pages and Bots
PR #492 fixes the gh-pages publishing race so every writer retries instead of losing and silently failing. PR #35 also bumps chess-bot to sphere-sdk 0.15.0 and documents the journal mount for clarity on bot state persistence. These are smaller reliability and documentation fixes that reduce operational friction alongside the larger SDK migration.
sphere, sphere-infra

Testnet2 Backup and Alerting Hardening
PR #22 adds backup for the BFT root consensus state on testnet2, closing a gap where it was never actually being backed up. PR #30 makes the MongoDB backup on testnet2 actually run and adds alerting for when it fails, fixing a silent failure mode. These two PRs directly address data-loss risk on testnet2 by ensuring both consensus state and database backups are verified and monitored. This is foundational reliability work ahead of further protocol changes.
bft-terraform, bft-ansible
Testnet2 Hard Fork and SDK 3.0.1 Rollout
PR #29 bumps the aggregator to sha-ae08165 implementing the leaf-value hard fork and pins DEFAULT_REQUEST_TTL, while #21 updates the testnet2 gateway image to 8cf25d4-cfg1 running java SDK 3.0.1. PR #78 upgrades java-state-transition-sdk from 1.4.2 to 3.0.1 in aggregator-subscription, aligning the Java stack with the same 3.x transition happening in the sphere ecosystem. This is a coordinated protocol-level upgrade spanning infrastructure config and application SDK versions. It sets up testnet2 for the leaf-value hard fork behavior.
bft-ansible, bft-terraform, aggregator-subscription
Aggregator CI Migration to Self-Hosted Runners
PR #79 moves the Build and Test plus Docker publish workflows onto the org's self-hosted runners, and #80 fixes an invalid docker-publish workflow caused by incorrect runner context usage in job env. These changes improve CI reliability and likely reduce build costs or queue times by moving off shared runners. The fix in #80 was needed immediately after the runner migration to unblock publishing.
