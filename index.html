AOS 2026.9.0 Release Shipped
The Community Edition release train landed with aos-ce #154 releasing AOS 2026.9.0 and oracles #58 enabling Oracle 2026.9.0 for published Astrid. Installer docs were updated across three PRs (#16, #15, #14) to ship the published Oracle bootstrap, align installer pins with CI, and use the released volume-layout base installer instead of interim builds. Release engineering hardening included aos-ce #158 draining tar listings when checking Distro signatures and #157 building the clean-home probe inside the GNU container to avoid host drift. Together these PRs ensure the public installer matches what was actually released and verified.
aos-ce, oracles, unicity-aos.github.io
Bootstrap and Oracle Diagnostics Fixed
aos-ce #161 allows credential-free Oracle host setup, removing a blocker for first-time bootstrap flows. #159 changes system inspection to read principal capsule metadata instead of reaching into private files, tightening the security boundary. oracles #59 improves diagnostics to correctly recognize when a packaged capsule is absent rather than misreporting the failure. #156 makes Community initialization resumable in bounded batches so interrupted bootstraps can continue instead of restarting from scratch. These changes collectively make first-run setup more robust and easier to debug.

Sphere6 PRs merged
Coinless NFT Support in Wallet Ledger
wallet-api #141 adds validation support for coinless (non-fungible) tokens at spec §8.2 step 6 and indexes token_type for lookup. #147 updates test fixtures to mint coinless tokens using the registry NFT type, clarifying that token_type names a class rather than a specific instance. #151 extends transaction history to accept coinless records while still enforcing the existing payment-request minimum for fungible transfers. Together these PRs bring first-class NFT handling through validation, indexing, history, and test coverage.
wallet-api
Migration Integrity Guardrail
wallet-api #150 pins migration checksums so that any edit to an already-applied migration fails fast in CI instead of surfacing as a boot-time crash in production. This shifts a class of dangerous schema drift bugs earlier in the pipeline, protecting deployments from silently broken migrations. It complements the coinless-token work by ensuring schema changes needed for the new token type stay verifiable and safe.
wallet-api
Sphere Infra Config and Provisioning Fixes
sphere-infra #41 introduces per-network paid-plan flags on sphere-site and removes the older flag they replace, cleaning up plan-gating logic. #40 fixes grafana-metrics to deliver a readable configuration and adds verification that provisioning actually landed, closing a gap where dashboards could silently fail to deploy. Both PRs improve operational reliability of the infra layer supporting the wallet-api services.

Fleet Rollout Reporting and Status API
jait91 shipped #307 adding a fleet rollout status API and #317 hardening fleet rollout reporting in the control plane for more reliable visibility into managed rule deployments. #301 adds a policy capture mode to the management API and #300 adds a deferred-analysis worker statistics API, giving operators deeper introspection into rule engine behavior and worker load. Together these expand observability across fleet-managed semantic rule deployments.
semanticd
Edge Rule Engine and Classification
jvsteiner's #320 compiles each organization's artefact from its own rules and enables the edge rule engine to run by default, a significant architectural shift toward per-tenant isolation. jait91's #316 adds edge classification support for managed rules, letting rules target edge-deployed contexts explicitly. These changes push more rule evaluation logic to the edge rather than centrally, improving latency and tenant isolation for managed policies.
semanticd
Rule Scoring and Coverage Bug Fixes
Automated fixes closed several correctness bugs in rule composition: #314 fixes ml_model rules that silently disabled the policy's global ML injection/jailbreak coverage when added (#311), and #312 fixes semantic_similarity rules being created and enabled with no evaluator present, so they screened nothing until now checked at creation instead of only at run-it (#310). #304 fixes effective-score computation where duplicate matches kept the first rule instead of the strictest, and a disabled variant could still tighten scoring (#302). #305 fixes unattached-rule UX after #296, covering both the missing library rules in 'Add an existing rule' and UI not reflecting newly enabled unattached rules (#303). These fixes remove several silent-failure modes in the rule engine that had left protections quietly non-functional.
semanticd
CI Board Automation Fix
jvsteiner's #313 fixes CI so that reopened issues correctly move to the 'In test' column on the project board, keeping triage state accurate. This is a small process fix but reduces manual board grooming for the semanticd team.
