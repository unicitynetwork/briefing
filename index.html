Oracle 2026.10 release train lands
A rapid succession of Oracle releases shipped: 2026.10.0 (#104, #105, #107), 2026.10.1 (#108), and 2026.10.2 (#113), each fixing codex startup authentication and AOS product selection issues along the way. PR #107 removed the dependency on a global b3sum binary for codex startup authentication, while #104 fixed detection of the AOS product from combined version output. AOS 2026.10.0 (#247) was prepared in parallel with authenticated Astrid stable, tying the oracle and AOS release trains together. This cluster reflects a tight release cadence driven by bugs discovered immediately after each prior release.
oracles, aos-ce
Channel-notice preflight checks fixed for installers
PR #112 fixed the capsule preflight logic to properly recognize dev-channel update notices, and #31 propagated that fix to the install site served at unicity-aos.github.io. Together these ensure users on the dev channel see correct update guidance instead of being blocked or misinformed during installation. This is a direct follow-up to issues surfaced by the Oracle release train shipping the same day.
oracles, unicity-aos.github.io
Codewall fails open after operator key revocation
PR #142 changes codewall's endpoint behavior so that a signed operator release is honored (fails open) even after the signing key has been revoked, provided the signature predates revocation. This addresses an edge case where legitimate releases could be incorrectly blocked once an operator's credentials are rotated or revoked. The change improves availability without compromising the security guarantee that revoked keys cannot sign new releases.
codewall

Payment intent failures never silently drop money moves
PR #837 fixes sphere-sdk so a send that may have moved money is never reported as a clean failure, closing a dangerous ambiguity window for callers. PR #170 documents the corresponding wallet-api spec rule: every 4xx response from the intent PUT endpoint precedes any write, giving clients a clear unconfirmed-PUT contract to reason about retries safely. Together these changes (cross-referenced via #835) harden the payment intent lifecycle against double-spends or lost-money scenarios caused by ambiguous error handling.
sphere-sdk, wallet-api
CI unblocked after MinIO registry login requirement
PR #174 pins wallet-api's CI to pgsty's community MinIO build after quay.io's official minio/minio image started requiring authentication, breaking unauthenticated pulls in CI. This is a straightforward infrastructure fix to keep the build pipeline green.

Semanticd harmful-content and injection detection training
A large batch of model training work advanced semanticd's prompt-injection and harmful-content defenses: #500 pins a retrained harmful-content model (d59485eb), #499 adds round-3 injection techniques covering obey/comply/revoked-rules patterns, and #492 splits injection fillers to compose hidden instructions. Supporting data quality work includes #497 drawing persona prompts from in-the-wild regular prompts, #496 relabeling mislabelled injection sources in older translations, and #498 scoping DLP actions to only trigger on place/company names adjacent to personal data (#292). semanticd
Semanticd fleet operations: bulk revoke and reload stability
PR #490 adds fleet-management capabilities to semanticd: bulk revoke, triggering an operator release on revoke, filters for stale/superseded entries, and token purge. PR #491 complements this by allowing capsule reloads time to complete during e2e test setup, reducing flaky test failures tied to the new revoke/reload flows. Together these improve operational control over fleet-wide model and token lifecycle management.

This is a coordinated core-to-infra rollout of a consensus correctness fix.
