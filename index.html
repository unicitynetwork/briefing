Frontend Protocol Adapter Layer Split
PR #82 refactors the frontend integration layer in unicity-aos by splitting monolithic protocol adapters into discrete, focused units. The change targets the hooks architecture, separating concerns so each adapter handles a single protocol boundary. This improves maintainability and makes it easier to add or swap protocol adapters independently going forward.
unicity-aos
Sphere19 PRs merged
Announcement Rendering and Line-Break Fidelity
A cascade of fixes and propagations addressed how announcements are rendered across the Sphere frontend ecosystem. PR #28 in sphere-ui corrected the announcement modal to display the full body content rather than the truncated popover summary, while PR #29 ensured every markdown element a body can contain receives proper styling. PR #30 then added preservation of author-typed line breaks, a regression that had been silently collapsing intentional formatting. The updated sphere-ui 0.1.43 and 0.1.44 were subsequently propagated via chore bumps into sphere (#482, #483), sphere-quest-frontend (#23, #24), sphere-dev-portal (#45, #47), and sphere-backoffice, ensuring all consumers picked up the corrected rendering pipeline.
sphere-ui, sphere, sphere-quest-frontend, sphere-dev-portal, sphere-backoffice
Moderation Flow Accuracy and Announcement Origin Filtering
Several PRs tightened the correctness and usability of the moderation and announcement subsystems. PR #86 in sphere-api ensured that approval messages are properly carried through into the resulting announcement record rather than being lost at the transition boundary. PR #88 fixed misleading copy in the approval notice that incorrectly promised players and earnings metrics to newly approved projects. On the backoffice side, PR #45 replaced a visual mock in the announcement preview with the real modal card component, eliminating discrepancies between preview and production appearance. PRs #87 and #46 added origin-based filtering to the announcement admin list, defaulting to manual announcements, so operators can distinguish system-generated entries from hand-crafted ones at a glance. PR #46 in sphere-dev-portal also stopped pinning the moderator approval note to the status banner, which had caused it to appear intrusively out of context.
sphere-api, sphere-dev-portal, sphere-backoffice
Inclusion-Proof Termination and SDK Stability Fixes
PR #740 fixed a correctness bug in the token-engine where the inclusion-proof wait could fail to terminate, leaving callers suspended indefinitely past their intended deadline. PR #738 corrected payment logic so that pinned tokens are excluded from spendable balance calculations, and updated the refusal message to clearly communicate that reason to the caller, closing issue #737. PR #742 then bumped the dependency on state-transition-sdk to 2.0.3, removed a local workaround that had been masking an upstream deficiency, and added tolerance for transient gateway responses so the SDK degrades gracefully under intermittent connectivity rather than hard-failing.
sphere-sdk

waitInclusionProof Deadline Settlement Guarantee
PR #141 in state-transition-sdk-js resolves issue #140, where the waitInclusionProof function could fail to settle when its deadline elapsed, leaving promise chains unresolved. The fix ensures the function always settles — either with a result or a rejection — at or before the configured deadline, providing a reliable termination contract for all callers. This is the upstream change that unblocked the removal of the local workaround consumed by sphere-sdk PR #742.
