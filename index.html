Sphere Owns and Disposes Its Token Registry
PR #767 refactors Sphere's registry ownership model so each Sphere instance owns its token registry outright rather than sharing a reference. Calling destroy() now properly disposes the registry, closing a resource-leak gap in long-running or repeatedly instantiated Sphere sessions. This tightens lifecycle management and makes cleanup semantics explicit and predictable for consumers of the SDK.
sphere-sdk
Unicity Network23 PRs merged
Testnet2 Migration to Dedicated Server Infrastructure
A coordinated infrastructure cutover moved testnet2 off AWS onto a dedicated server, executed in two phases. Phase A (bft-ansible #32) brought the dedicated server live on 2026-09-02, while Phase B (bft-terraform #24, #25) applied the declarative Gandi DNS A record and then tore down the AWS stack, leaving Terraform state tracking only the Gandi record. This eliminates AWS hosting costs for testnet2 while keeping DNS management fully declarative and auditable.
bft-terraform, bft-ansible
Dashboard Rule Authoring: Cloning, Ruleset Ownership, and Modals
A cluster of dashboard features improves how operators author and manage rules. PR #253 lets users start a new rule from an existing one directly on the form, PR #246 adds cloning a single rule into a ruleset the user owns, and PR #242 converts the ruleset create/clone flows into modals for a smoother workflow. PR #254 rounds out the dashboard with a restyled dropdown, layout fixes for shorter screens, and corrected navigation links. Together these changes reduce friction in the most common rule-authoring tasks.
semanticd
Audit Log and RBAC Filter Bugs Fixed
Several audit and access-control defects were closed out. PR #238 fixes audit records never storing session_id, which had made the Session ID filter unusable, and PR #236 fixes the API Key filter returning zero results because the dashboard sent the full key while audit stored only the prefix. PR #235 resolves a 403 blocking operators from creating rules, conflicting with the intended 'operator edits everything except users' policy, and PR #241 adds RBAC documentation follow-ups from that fix. These fixes restore trust in audit search and clarify role boundaries.
semanticd
API Error Handling Hardened Against Leaks and Wrong Codes
Multiple fixes correct API error semantics and information exposure. PR #245 reorders validation so malformed requests return 422 instead of masking as 403 for unauthorized callers, PR #229 stops leaking raw sqlx error text in 500 response bodies, and PR #213 makes a taken policy name return a proper 409 instead of a raw 500. PR #216 also allows deleting an agent class so its associated policy can be removed too. These changes make the API's error contract more correct and secure for clients.
semanticd
CI Pipeline Reliability and Build Fixes
A set of CI/build fixes targets flaky and hanging pipelines. PR #248 drops the pip cache from the Python SDK job so a timed-out restore no longer hangs the runner, PR #244 serializes same-named cargo jobs across concurrent runs, and PR #243 stops a disk-pressure cleanup step from wiping other concurrent runs' target directories. PR #247 fixes demo builds to include the ml feature so the Detectors page stops hiding half the pipeline, and PR #230/#231 update e2e tests to follow a plane refactor and purge stale cargo fingerprints in Docker builds. These fixes collectively reduce CI flakiness and wasted runner time.
semanticd
Rules and Audit UI Bug Fixes
Smaller UI-focused fixes close out gaps in the rules and audit experience. PR #252 fixes the row-actions menu on the Rules table being clipped by the scroll container, and PR #251 fixes the rule detail page being view-only with a broken 'Run it' bench that failed with PolicyRequired. These polish fixes remove friction points operators were hitting in day-to-day rule management.
semanticd
