Security Policy Published for AOS
PR #5 adds a SECURITY.md file to the unicity-aos repository, documenting security guarantees, assumptions, and known limits of the system. It also establishes a clear process for responsibly reporting vulnerabilities. This gives external researchers and integrators a formal channel and reduces ambiguity about what security properties the system actually provides. A foundational step for hardening the project's security posture as it matures.
unicity-aos
Sphere2 PRs merged
Bridge Hardening: Correct Token Burns
PR #554 fixes a bug in the bridge's burn logic, ensuring only the token actually holding the displayed amount is burned. Previously there was risk of burning a mismatched token, which could lead to incorrect balances or fund loss during bridging operations. This change tightens the invariant between displayed and actual token state before destructive operations execute. Critical correctness fix for cross-chain asset transfers.
unicity-sphere
WalletConnect Session Recovery Fix
PR #552 fixes an edge case where a WalletConnect session restored without its original methods would fail to terminate properly. The bridge now correctly ends such sessions instead of leaving them in a broken or lingering state. This prevents stuck connections and improves reliability of wallet reconnection flows. Both PRs #554 and #552 were authored by @MastaP and target robustness in the bridge's wallet and token-handling logic.
