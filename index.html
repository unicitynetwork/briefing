Astrid2 PRs merged
Schema namespace and installer host migration off codewall.dev
PRs #14 and #13 together complete the detachment of the artefact schema $id namespace and installer host from the codewall.dev domain. #14 moves the schema identifiers and installer references to the new namespace, ensuring downstream consumers resolve schemas against the correct authority. #13 enforces D3.25: a single check runs in exactly one place and a single deployment follows exactly one analysis path, eliminating ambiguity in the execution topology. Together these changes harden the AOS configuration contract ahead of any public release.
unicity-aos
Sphere1 PRs merged
Payment confirm screen source-blob prewarming
PR #754 introduces prewarming of source blobs triggered from the payments confirm screen in the Sphere SDK. By fetching and caching the required blobs before the user completes confirmation, the feature reduces latency on the critical payment completion path. This is a targeted performance improvement that front-loads I/O work into idle time the user spends reviewing the confirm screen, avoiding a cold-fetch stall at the moment of submission.

Unicity Network14 PRs merged
Console dashboard rebuilt and closed against management API
PRs #134 and #128 form the core of a full console rebuild: #134 reconstructs the frontend against the current design of record, while #128 closes the functional gaps between the console UI and the management API so every API capability is reachable from the dashboard. #127 fixes a session-hygiene bug where sign-out was only clearing state client-side, leaving the server-side session alive; it now terminates the session at the server on sign-out. PR #132 adds a guard preventing an admin from revoking its own console access, and #133 enforces that PATCH cannot deactivate a resource — deactivation is only permitted through the POST routes. These changes collectively make the console a trustworthy and complete operator interface.
semanticd
In-console user guide behind ⌘K command palette
PR #142 ships a user guide rendered directly inside the semanticd console, surfaced through a ⌘K command-palette shortcut, giving operators searchable documentation without leaving the UI. #143 adds CI publishing of that guide on the self-hosted runner so the built artefact is always up to date with the codebase. #144 fixes a Docker stage ordering bug in which the dashboard build stage did not yet have the docs corpus it was now expected to read, causing the guide to be absent from the container image. Together these three PRs deliver and operationally stabilise the embedded documentation experience.
semanticd
Analysis engine: heavy detectors isolated, compile errors enforced
PR #131 restructures the analysis centre so that heavy detectors run exclusively there rather than being duplicated across execution paths, sharpening the separation of responsibilities introduced in the AOS area-3 work. The same PR promotes a rule that fails to compile from a warning to a hard error, preventing silent analysis gaps when rule syntax is broken. PR #137 by @jait91 fixes a race condition in the inference worker pool where workers could miss jobs that had been queued before the worker polled, improving throughput reliability under load. PR #126 addresses eight specific findings from the second review pass on #120 covering the plane and database layers.
semanticd
Schema namespace migration and CI/docs housekeeping
PR #139 re-vendors artefact.schema.json to align the $id field with the new namespace established in unicity-aos #14, keeping the schema reference canonical across both repositories. #138 fixes a CI regression in the migration test suite that was incorrectly asking Docker for a container it no longer needed, restoring clean test runs. #140 drops a now-stale caveat in verify-artefact.sh that warned about an unmerged codewall-design PR, reflecting that the upstream work has landed. These cleanup PRs reduce noise in CI output and keep the documentation and tooling accurate after the namespace migration.
