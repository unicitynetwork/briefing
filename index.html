Astrid3 PRs merged
Signed macOS app packaging and installer flow
PR #155 carries the signed filesystem app through the build pipeline and installs it correctly on macOS. This closes a gap where the app bundle either wasn't properly signed or wasn't correctly staged before installation, which matters for Gatekeeper compliance and smooth end-user installs. The fix ensures the packaged artifact matches what was actually signed, avoiding runtime trust failures.
aos-ce
Oracle lifecycle fix and 2026.9.0 release prep
PR #57 changes the oracle's automatic startup to use a session-owned lifetime rather than a longer-lived or detached one, fixing potential issues where the oracle process outlives or is orphaned from its owning session. PR #56 prepares the Oracle 2026.9.0 release, including updated release notes and a defined runtime identity for the build. Together these harden process lifecycle management ahead of shipping the next oracle release. No release was cut yet, but the groundwork is merged.
oracles
Sphere3 PRs merged
Subscription catalogue now drives plan availability
PR #515 shifts control of what's on sale to the catalogue itself, and both #515 and #513 add explicit naming of the network to subscription flows. PR #513 further restricts plan offers to only those that are actually purchasable in the current context, preventing users from seeing unbuyable options. This consolidates subscription business logic so the catalogue is the single source of truth for saleability. It reduces mismatches between displayed plans and actual purchase eligibility.
sphere,sphere-api
Cleanup of dead network configuration value
PR #90 removes the unused `dev` value from the SPHERE_NETWORK configuration enum, eliminating a stale option that no longer maps to any real environment. This is a small hygiene fix but reduces confusion for anyone configuring or debugging network settings. It complements the network-naming work landing in the subscription PRs this same cycle.
sphere-api
Unicity Network7 PRs merged
Endpoint inventory and revocation APIs land
PRs #297 and #295 add new endpoint inventory read APIs and a paginated endpoint list/detail API, giving consumers structured, scalable access to endpoint data instead of unbounded dumps. PR #293 fixes endpoint revocation (issue #287), closing a bug where revoked endpoints weren't being handled correctly. Together these three PRs strengthen the endpoint management surface with better querying and correct lifecycle handling. This is foundational work for any UI or automation that needs to enumerate or manage endpoints reliably.
semanticd
Codewall policy publishing made atomic
PR #294 changes how Codewall policies and edge artefacts are published so the operation is atomic, preventing partial or inconsistent policy states from being visible to consumers mid-update. This closes a class of race conditions where edge nodes could observe a half-applied policy set. It's a reliability improvement for policy distribution across the network.
semanticd
Rules lifecycle UI fixes and demo panels
PR #298 fixes two rules lifecycle UI bugs (issue #296): the rule page no longer allows enable/disable actions it shouldn't, and rules removed from their last ruleset are no longer stranded and unrecoverable. PR #299 ports the sif-dash demo panels into the product, gated behind an off-by-default switch so they don't affect production users yet. These changes improve correctness of rule management while safely staging new UI experiments for later rollout.
semanticd
Upgrade runbook documentation refreshed
PR #291 updates the upgrade runbook so it accurately describes the current deployment topology and steps, replacing outdated or generic guidance. This reduces operational risk during upgrades by ensuring operators follow instructions that match the real environment. It's a documentation-only change but directly supports safe, repeatable deployments.
