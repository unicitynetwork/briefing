Codewall network path hardening
A cluster of fixes tightened how Codewall routes and identifies its production traffic. PR #12 pins the production Codewall host to prevent DNS or config drift, PR #11 routes HTTPS through the capsule net for better isolation, and PR #6 moves the plane host off third-party infrastructure onto a domain the team controls. PR #10 aligns the Codewall artifact envelope format to fix a mismatch. Together these changes reduce reliance on external infrastructure and close gaps in how Codewall traffic is authenticated and routed.
unicity-aos
Dependency bumps for Codewall
Routine dependency maintenance kept Codewall's Rust toolchain current. PR #8 bumps blake3 from 1.8.6 to 1.8.7, PR #5 bumps uuid from 1.24.0 to 1.25.0, and PR #3 bumps toml from 0.9.12+spec-1.1.0 to 1.1.4+spec-1.1.0. These are automated dependabot updates that patch minor versions without functional changes to Codewall itself. Keeping these libraries current reduces exposure to upstream bugs and security issues.

Unicity Network12 PRs merged
Semanticd security and policy enforcement fixes
A batch of fixes closed several policy-bypass and access-control gaps in semanticd. PR #165 prevents a zero-width character bypass in prompt-injection detection, PR #166 requires explicit intent before allowing model data extraction, and PR #158 enforces policy rollout mode at runtime so staged policies can't be skipped. PR #171 validates agent class bindings against the registry to stop misconfigured agents, and PR #172 hides the Access navigation from operators who shouldn't see it. These changes collectively harden semanticd's core policy engine against both malicious inputs and misconfiguration.
unicitynetwork
Dashboard UX and rule override fixes
Dashboard-facing fixes improved how operators interact with rules and navigation. PR #168 ensures overrides are correctly applied when toggling built-in rules instead of being silently ignored. PR #157 pins tabs, lifts bulk verbs into view, and stops a UI bar from popping in unexpectedly, cleaning up a rough interaction pattern. PR #164 restores the checksum for migration 22 in the database layer, fixing a data-integrity issue tied to schema history. These fixes make the operator-facing dashboard more predictable and trustworthy.
unicitynetwork
Aggregator and SDK wire-format correctness
Cross-repo work tightened correctness guarantees around certified transactions and inclusion proofs. In aggregator-go, PR #182 binds inclusion proofs to the certified shard and network and returns referenceTime on block records, closing a gap where proofs could be replayed across contexts. In state-transition-sdk-js, PR #146 binds service time and enforces request timeouts to prevent stale or hanging requests, and PR #147 simplifies the certified-transaction wire format while adding a real-aggregator test for #146. Together these changes make the certification pipeline more robust against cross-shard replay and timing issues.
aggregator-go, state-transition-sdk-js
Plane fingerprinting and polling improvements
PR #163 changes the plane component to fingerprint over key bytes rather than a coarser representation, improving accuracy of identity checks, and introduces a configurable poll cadence so operators can tune how frequently the plane polls. This gives more control over the tradeoff between responsiveness and load. It's a smaller, standalone improvement to the plane subsystem's reliability and flexibility.
semanticd
