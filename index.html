Astrid2 PRs merged
CI hardening and operator notification as-built record
PR #9 strips ripgrep out of the e2e pipeline in favor of fail-closed grep, and isolates native observations so a missing tool can no longer let checks silently pass. PR #17 delivers the operator notifications workflow end-to-end: the mock now serves the actual route, the folder structure points at it correctly, and an as-built record documents what was actually shipped versus designed. Together these tighten both test-suite reliability and the traceability of notification design decisions. This closes gaps where CI could pass on missing native checks and where design docs drifted from implementation.
codewall, codewall-design
Sphere3 PRs merged
Wallet balance and seal cache correctness fixes
PR #132 reverts the §8.2 worker pool in validation because it was partitioning the seal cache, a regression that risked incorrect seal lookups during validation. PR #756 fixes balance refresh in sphere-sdk so the displayed balance updates continuously while a drain operation runs, rather than jumping only at completion. Both PRs target correctness of financial state during concurrent or long-running operations. This reduces the risk of stale or fragmented state being shown or used mid-transaction.
wallet-api, sphere-sdk
Multi-token receive UI stability
PR #491 caps the toast notification stack so that receiving multiple tokens in quick succession can no longer stack enough toasts to cover the wallet UI. This is a targeted UX fix for a race condition between notification volume and screen real estate during multi-token receive flows. It ensures the wallet remains usable and visible even under bursty incoming-token activity.
sphere
Unicity Network9 PRs merged
Agent class policy engine ships across SDKs
PR #151 introduces agent classes as the fundamental unit of policy, with #152 adding dedicated wire codes so class-policy refusals are distinguishable on the wire rather than generic errors. PR #155 extends this to fleet management, enabling bulk assignment of keys into a class while fixing visual defects that were blocking the feature. PRs #154 and #156 bring the Python SDK to installable, contract-checked, drop-in status and then bring TypeScript, Go, and Rust SDKs to parity with it, so the new class-policy model is usable consistently across all four languages. This is the core policy infrastructure rollout for the release, spanning server-side semantics through client SDK parity.
semanticd
Docs and operator alerting for policy failures
PR #153 removes three documentation pages that described API error codes which never existed, cleaning up a source of developer confusion around the policy API surface. PR #150 adds an operator notification triggered when a rules compile failure occurs, automatically resolved on recovery, giving operators real-time visibility into policy compilation health. Both PRs support the reliability and clarity of the new agent-class policy system landing alongside them. Together they reduce both documentation drift and blind spots in production monitoring.
semanticd
Aggregator timeout enforcement and decode cleanup
PR #178 binds service time tracking and enforces request timeouts in aggregator-go, preventing requests from hanging indefinitely. PR #180 follows up with cleanups identified while reviewing #178: switching to a single-pass CBOR decode for efficiency, setting a sensible TTL default, and dropping an unused metric. These changes improve both the robustness of request handling and the internal code quality of the aggregator's decode path. The timeout enforcement in particular closes a reliability gap for slow or stuck upstream calls.
