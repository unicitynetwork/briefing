Astrid38 PRs merged
Signed 2026.9.0 release pipeline hardened end-to-end
A major release push locked down AOS Community Edition 2026.9.0, covering version bump (#122), 22 required capsule artifacts (#123), schema-v2 executable naming and aos-mcp membership (#125), and fail-closed enforcement when stable archives lack Distro.sig (#118). Signing and distribution were secured with signed Distro.lock/Distro.sig planted into immutable releases (#128), signed rehearsal asset production (#50), signed GNU rehearsal archive export (#137), and machine-readable rehearsal checksums (#138). Platform coverage was rounded out with GNU FUSE (#139) and Darwin FSKit (#136) providers, musl compatibility validation (#119), Linux glibc baseline enforcement (#59), and cross-target archive sealing with native runtime (#120). This gives operators a reproducible, cryptographically verifiable release process across Linux and Darwin targets.
aos-ce, oracles
Rehearsal journey validates packaged volume install/runtime
A new rehearsal framework simulates real packaged installs, starting with the packaged Linux FUSE volume journey (#143) completed and extended to aarch64 (#145) and matrix GNU packaged volume targets (#148). Fixes bound the sealer target to the correct archive (#146), bound the socket path (#149), and pinned rehearsal to the landed Astrid runtime and candidate (#135, #142, #131, #134). Supporting fixes chmod artifacts before execute bind (#132), invoke the archive validator via Python (#133), and require Astrid 2026.9.0 capsule archive members (#130). Together these PRs give CI confidence that installed volumes actually boot and behave before shipping.
aos-ce
Runtime lifecycle: stop, shutdown, launch made reliable
Runtime correctness fixes tighten how Astrid starts, stops, and persists. #126 confirms stop after every delegated shutdown, #121 requires stopped Astrid volume mode 0600, and #127 applies signed Unicity CE with volume-only stop. #124 fixes install to launch Astrid from the immutable release runtime/bin path, and #141 persists the versioned GNU FUSE runtime. #115 hardens MCP serve forwarding and lifecycle handling. These changes reduce risk of stale processes, unsafe permissions, or launching from the wrong binary path.
aos-ce
CI/oracle guardrails: channels, auth, checksums
Operational CI safety nets were added: warn instead of fail for unpublished nightly channel (#150), warn before signed channels expire (#147), and a prepare-only Darwin rehearsal sign workflow (#129). Oracle service hardening includes authenticating capsule metadata queries (#52) and entering the product workspace before identity preflight (#51). #140 corrects the Community capsule count in release accounting. These changes catch release and auth issues earlier without blocking unrelated CI runs.
