Astrid3 PRs merged
Hardened install and upgrade resilience
PR #163 ensures the installer waits for upgrade custody to be properly handed off before a new protocol version installs, preventing race conditions during upgrades. PR #162 adds retry logic for readiness probes that are blocked by a cold runtime, avoiding premature failure reports. Together these two codewall fixes make the install and upgrade pipeline more robust against timing issues. PR #256 in aos-ce closes a security gap where chained or multi-line shell commands could slip past shell checks, tightening command validation before execution.
codewall, aos-ce
Sphere2 PRs merged
Bot knowledge refresh and SDK wallet fix
PR #53 updates the agentic-chatbot to commit a7bb246, refreshing its RAG knowledge base so responses reflect the latest documentation and context. PR #32 fixes the SDK connect example so a pubkey recipient is left bare instead of being incorrectly prefixed with '@', correcting a formatting bug that could break recipient resolution. These are unrelated but both small, targeted fixes improving developer-facing tooling accuracy.
sphere-infra, sphere-sdk-connect-example
Unicity Network17 PRs merged
UC consolidation across aggregator and SDK stack
A major cross-repo effort lands unicity certificate (UC) consolidation: aggregator-go #222 adds get_inclusion_proofs.v1 with retained views, reference consolidation, and proof status hints (building on #188, #209); bft-core #35 and bft-go-base #12 add partition view sidecars and authenticated reconstruction with strict signature verification to support this at the consensus layer. state-transition-sdk-java #89 and state-transition-sdk-rust #38 and state-transition-sdk-js #169 bring the same UC consolidation, proof status hints, and strict single-pass signature verification to each client SDK, with SP1 acceleration added on the Rust side. aggregator-subscription #86 extends the gateway to support batch proofs, non-inclusion proofs, and long-poll reads, tying the consolidation work into the subscription service. This is the backbone release enabling consistent, verifiable proof semantics across every language SDK and the core consensus layer.
state-transition-sdk-java, aggregator-subscription, state-transition-sdk-rust, state-transition-sdk-js, aggregator-go, bft-core, bft-go-base
Non-inclusion proofs land across all SDKs
Non-inclusion proof support is now implemented end-to-end: aggregator-go #223 adds get_non_inclusion_proof.v1, built to be compatible with the rugregator/Rust SDK. state-transition-sdk-rust #39 adds strict context, typed errors, and a per-seal quorum memo for non-inclusion handling, while state-transition-sdk-js #170 ships the corresponding non-inclusion client and verifier (J1). This feature lets clients cryptographically prove that a given state does not exist in the tree, a critical complement to inclusion proofs for completeness guarantees.
state-transition-sdk-rust, state-transition-sdk-js, aggregator-go
Long-poll waiting for inclusion proof reads
A set of review-only PRs introduces long-poll inclusion-proof reads via a new waitMs parameter, moving proof retrieval from pure polling toward long-poll semantics with a path toward non-inclusion support: aggregator-go #234, state-transition-sdk-rust #45, and state-transition-sdk-js #177 all implement this pattern consistently. state-transition-sdk-java #89 bundles UC consolidation, non-inclusion proofs, and long-poll waiting together in a single parity PR merging sdk-parity into main. This reduces client-side polling overhead and improves latency for proof availability checks across the SDK ecosystem.
state-transition-sdk-rust, state-transition-sdk-js, aggregator-go, state-transition-sdk-java
Health semantics and quality-of-life fixes
semanticd #519 clarifies that content receipt counts do not indicate detection coverage under full erasure, correcting a potentially misleading codewall warning. semanticd #518 fixes flaky inference_pool tests by properly waiting for pool state across three cancellation and timeout test cases. aggregator-subscription #89 refines health check semantics so an overloaded shard is reported as busy rather than unhealthy, avoiding unnecessary failover. state-transition-sdk-java #85 refreshes the README for better onboarding clarity.
semanticd, aggregator-subscription, state-transition-sdk-java
