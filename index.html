Wallet-agnostic balance labels
PR #543 reworks wallet labeling logic to be wallet-agnostic, removing assumptions tied to a specific wallet implementation. This generalizes label display so it works consistently across different wallet backends. The change is authored by @lploom and sets up Sphere's UI to support multiple wallet types without special-casing label logic.

Unicity Network45 PRs merged
Asymptotic performance overhaul across aggregator, SDKs, and BFT core
A sweeping performance initiative led by @ristik spans nearly every core repo, replacing linear scans with indexed structures and incremental algorithms. Key changes include persistent layered SMT overlays and incremental overlay collection (aggregator-go #202, #204), batched disk proof union-path builds (#203), indexed retention catalogs with O(1)/O(log V) admission (#200), and indexed publication digest lookups with a production catalog accountant (#205, #208). On the SDK side, certificate interning, flat shard trees, and lazy certificate decoding cut redundant work in both Rust (#25, #24) and JS (#158, #157, #156). bft-core and bft-go-base gain shared sidecar certification senders, bounded view retention, and O(S log S) shard scheme validation (#33, #32, #31, #30, #29, #9, #8, #7). These changes close out the asymptotic-complexity acceptance gaps and measurably reduce ECDSA verifications, memory, and RocksDB/D1 costs (#26, #206, #199).
aggregator-go, state-transition-sdk-rust, state-transition-sdk-js, bft-core, bft-go-base
Authenticated partition views and trust-base security hardening
A security-focused track introduces authenticated partition views flowing from candidate to authenticated to assembly state, implemented across bft-go-base (#8), aggregator-go (#197), and both SDKs (Rust #22, JS #155). This makes pinned topology optional while still authenticating UCs and partition views at the intake boundary. Complementary hardening lands trust-base anchoring on the installed chain, rejecting REST genesis, wrong-epoch, or wrong-network data (aggregator-go #198). PartitionViewV1 codec and shard-tree reconstruction work (bft-go-base #7, SDK #21/#154) underpins the whole authentication chain, ensuring consolidated proofs can't be forged or replayed.
aggregator-go, state-transition-sdk-rust, state-transition-sdk-js, bft-go-base
Proof consolidation pipeline: CertificationResponseV2 to inclusion proofs
This theme delivers an end-to-end proof consolidation pipeline, starting with bft-core's CertificationResponseV2 transport and negotiation (#29), captured sidecars (#30), and deterministic producer fixtures (#31). aggregator-go builds retained finalized read views, RocksDB-backed read views, a pure consolidation library, and the get_inclusion_proofs.v1 JSON-RPC endpoint (#189, #191, #190, #193, #192, #196), culminating in a client/CLI/docs package (#194) and a portable fixture corpus for testing (#195). Both SDKs add explicit proof consolidation clients with batch capability and master-first orchestration (Rust #23, JS #156/#157). This closes the loop from raw certification responses to consumable, verifiable inclusion proofs for downstream clients.
aggregator-go, bft-core, state-transition-sdk-rust, state-transition-sdk-js
Bridge vault safety: capped amounts, balance checks, witness validation
Three PRs by @lploom harden the bridge vault against fund-safety risks. #29 adds a check that vault balance moves by exactly the transferred amount on every transfer, catching skimming or miscalculation bugs. #30 caps lock amounts at uint64 in the vault and rejects oversized amounts earlier at the plugin layer. #31 ensures a configured service refuses raw witnesses and relayers verify lock references before proving, closing a validation gap in the proving pipeline.
unicity-bridge
Semantic firewall: jailbreak and prompt-injection detection rules
@MastaP extends semanticd's rule engine to catch adversarial prompt patterns. #503 flags an Arabic-language 'assistant without rules' developer-mode jailbreak attempt (issue #237), while #502 detects directives instructing the model to obey only the sender (#488). #501 introduces a broader prompt-injection model covering extraction, output forcing, and stale/hidden instructions. These additions tighten semanticd's defenses against increasingly sophisticated prompt manipulation.
