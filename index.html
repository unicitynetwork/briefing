Astrid clock backs HTTP deadline handling
PR #23 switches the protocol layer to use the Astrid clock for computing and enforcing HTTP deadlines, rather than relying on system wall-clock time. This makes deadline calculations resilient to clock skew and drift across nodes, which is critical for consistent timeout behavior in distributed request handling. The fix targets correctness in how expiry windows are derived for outgoing and incoming HTTP calls.

Unicity Network6 PRs merged
Mainnet launch refresh across infra layers
PR #23 in bft-terraform and PR #31 in bft-ansible together deliver a coordinated mainnet infrastructure refresh, moving to a 4-shard fleet topology. The changes add environment-isolated backups, CloudTrail logging, and a new gateway build (8cf25d4 in terraform, ae08165 in ansible), plus hardened monitoring and backup procedures. This establishes a cleaner, auditable baseline for running the 4-shard mainnet fleet with stronger operational guardrails.
bft-terraform, bft-ansible
Explorer and rate-limiter mainnet readiness fixes
PR #3 in smt-explorer adds Mainnet network support to the SMT explorer and retires the legacy v1 Testnet, aligning the UI/backend with the current network landscape. PR #81 in aggregator-subscription fixes a dangerous edge case where a zero rate limit was silently treated as unlimited (falling through to a 500 error) instead of correctly blocking all traffic. Both changes tighten correctness ahead of broader mainnet rollout, closing gaps in observability and traffic control.
smt-explorer, aggregator-subscription
Rust SDK timeouts and e2e CI alignment
PR #19 restores the e2e/ test suite to a working, in-sync state and brings it under CI coverage, while also removing an outdated upgrade section from docs. PR #18 binds service time handling and enforces request timeouts in the Rust state-transition SDK, aligning its wire behavior with already-shipped SDKs in other languages. Together these changes improve test rigor and ensure the Rust SDK behaves consistently with peer implementations under timeout and latency conditions.
