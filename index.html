Astrid1 PRs merged
AOS bootstrap authentication hardened
PR #45 fixes oracle authentication during AOS bootstrap and Codex attach flows. Previously the bootstrap and attach sequences lacked proper authentication checks, exposing a gap in the oracle trust chain. This closes that gap, ensuring only verified actors can attach during startup. A small but security-critical fix for the oracle subsystem.

Sphere3 PRs merged
Onboarding collapses to one plan screen
PRs #499 and #500 rework the subscription onboarding flow so users buy a plan on a single consolidated screen instead of being pushed an on-entry offer. #500 removes the upfront plan offer and gates the restore-purchases step behind actual plan state, avoiding showing restore options to users who don't need them. #499 implements the one-screen plan purchase experience referenced in issue #496. Together these simplify the funnel and reduce friction for new users converting to paid plans.
sphere
Sphere SDK drops global state for concurrency
PR #772 is a breaking refactor that eliminates the last process-global state from the Sphere SDK, moving to a model of one Sphere instance per network that is disposable and concurrent-safe. This enables multiple isolated Sphere instances to run safely within the same process without cross-contamination. It's a significant architectural change (breaking change, denoted by the `!`) that unlocks safer multi-network and multi-threaded usage patterns going forward.

Unicity Network8 PRs merged
Policy and ruleset editing overhaul
A cluster of fixes reworks how rulesets and policies are managed in the dashboard. #269 adds proper UI for managing rules from a ruleset (add new, add existing, edit) and broadens ruleset editing capabilities (issue #261). #266 fixes a bug where removing a ruleset from a policy had no real effect until the ruleset itself was deleted, meaning the guard kept enforcing stale rule compositions (issue #265). #259 fixes ruleset deletion being blocked by phantom policy attachments that were no longer visible in the UI (issue #258). #264 fixes an issue preventing creation of a policy with a name matching an archived one, and adds visibility/purge controls for archived policies (issue #263). #260 improves clarity of policy screen copy so the dashboard's language matches actual behavior.
semanticd
Fleet/Agents dashboard readability fix
PR #270 fixes the Fleet/Agents tab being overwhelmed by a massive 'Caller-led keys' list that buried the more useful agent-class view (issue #267). This improves usability for operators trying to scan agent classes rather than individual key entries. A focused UI fix addressing a real navigation pain point in the dashboard.
semanticd
CI reliability: autofix retries and issue reopening
Two CI-focused PRs improve automation robustness. #271 gates the autofix pipeline on Claude's actual exit code, adds verification before shipping fixes, and retries when hitting quota-related failures, reducing false-positive merges. #255 ensures issues auto-closed by a merge are reopened and tagged awaiting-testing, preventing premature closure before validation. Both PRs by @jvsteiner tighten the feedback loop between automated fixes and human verification.
