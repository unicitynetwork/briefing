Bridge mints no longer vanish, lost ones recovered
PR #95 fixes an achievements bug where bridge mint events could be dropped and never credited. The fix stops new mints from being lost and adds recovery logic to backfill the ones that already slipped through. This closes a gap where users could complete bridge actions without receiving the corresponding achievement mint. Reliability of the achievements pipeline is restored for both past and future mint events.
sphere-api
Unicity Network8 PRs merged
Bridge settlement tracking survives restarts and bad RPCs
PR #43 makes broadcast settlements tracked by txid across service restarts, so a batch only fails once the transaction is confirmed not to land, eliminating false failures from transient restarts. PR #40 extends this: a settlement whose receipt can't be read now settles from the vault log using its txid, releases not submitted by the service only settle once a second RPC confirms them, and proofs are served only once the batch actually settles. Together these changes close several races and false-negative paths in the bridge's settlement logic, directly improving correctness of funds release and proof serving. This is foundational reliability work ahead of broader testnet2 rollout.
unicity-bridge
Testnet2 bridge ops: deploy pinned builds, alert on stuck state
PR #55 pins testnet2 to run the bridge on commit 9718459 and adds alerting for settlements stuck unmined. PR #54 rolls testnet2 forward to eecd385, adding a second RPC to confirm releases, mirroring the dual-RPC confirmation logic landed in unicity-bridge #40. PR #53 adds an alert for when the bridge marks burns settled without having its own txid, catching a dangerous settlement edge case. These three PRs keep the testnet2 deployment in lockstep with bridge safety fixes and add observability so stuck or unsafe settlements are caught quickly.
bft-ansible
CI build gating: only trusted refs build service images
PR #41 restricts the service image build to main, v* tags, and manual runs, so pull requests no longer trigger image builds. This reduces CI resource usage and prevents untrusted or in-progress PR code from producing published-looking images. It's a guardrail that tightens the supply chain for bridge service artifacts.
unicity-bridge
Dashboard CI greened, staging deploys gated on passing commits
PR #550 fixes the dashboard to get CI green on main, cleaning up the example and fixing the Tenants tab. PR #551 changes deploy automation so staging only rolls after CI passes on that exact commit, preventing broken builds from reaching staging. Together these restore confidence in the semanticd dashboard's build health and tighten the deploy pipeline's safety gate.
